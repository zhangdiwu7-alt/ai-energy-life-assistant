# AI Energy Life Assistant · 产品方案

> 性质：独立产品设计项目，一个整合家庭储能、语音交互与智能家居的 AI 能源生活助手概念设计。
> 与《交互原型》《系统实现报告》《AI 协作方法论》共同构成完整方案。
> 版本 V1.0

---

## 一、产品定位与战略

### 1.1 一句话定位

**AI Energy Life Assistant 不是新的设备遥控器，而是「家庭能源运营助手」。** 它基于用户授权的数据预测能源机会，在安全与舒适约束内生成可执行方案，经用户确认或既定授权后由设备平台执行，并以「预计节省 / 已验证节省 / 可信度」持续反馈。

### 1.2 市场机会

- 家庭用电成本持续上升，新能源（光伏、储能）渗透率快速提升。
- 现有智能家居 App 只关注「设备控制」，能源管理是高价值但被忽视的场景。
- 用户不知道如何优化用电，「AI 能帮我省多少钱」尚未被可信地量化。

### 1.3 差异化定位

传统竞品各自为政：

| 竞品类型 | 优势 | 短板 |
|---|---|---|
| 智能家居 App（HomeKit / Google Home 等） | 设备生态成熟 | 能源管理能力有限 |
| 能源监测 App（Emporia / Sense 等） | 用电监测精细 | 无第一方硬件生态，难以闭环执行 |
| 语音助手（Alexa / Siri / Google） | 语音交互成熟 | 与储能硬件无深度整合 |

**本方案的潜在结构性优势** 不是「能源 + AI + 语音」三个标签的简单叠加，而是在**同一账号与设备体系内**，把储能设备第一方能源状态、设备执行、停电保障、户外能源与结果验证连接起来，形成「发现浪费 → 安全执行 → 验证省钱」的完整闭环。

> ⚠️ 该优势是**待验证假设**，只有账号、API、固件与设备兼容范围真正打通后才成立。

## 二、目标用户分层

产品不以「是否拥有储能设备」作为唯一准入条件，而是按数据条件分层交付价值：

| 层级 | 可用数据 | 可交付价值 | 技术边界 |
|---|---|---|---|
| **L1 能源评估** | 账单、地区费率、家庭问卷 | 发现节省潜力、区间估算 | 不能声称实时监测或「已验证节省」 |
| **L2 能源连接** | 智能电表、兼容插座、电力公司数据 | 监测、异常识别、部分效果验证 | 缺少储能设备时不能调度光伏储能 |
| **L3 能源托管（核心）** | 储能系统、智能电表、电价、天气 | 预测、充放电建议、低风险执行、节省验证 | 仅支持能力注册与固件认证的设备组合 |

## 三、四大创新场景

### 场景 1：智慧用电优化（核心高频场景）

- **用户痛点**：峰谷费率、光伏发电、储能 SOC 与家庭负载关系复杂，用户看不懂、也不会调。
- **AI 价值**：预测未来 24 小时光伏与负载，由约束优化器生成充放电与设备运行计划。
- **商业价值**：提升储能设备使用价值、留存与扩容意愿。
- **差异化**：依托储能设备第一方能源数据执行策略，并把动作与实际节省关联。

### 场景 2：露营能源管家（移动 / 增长场景）

- **用户痛点**：理论容量与真实续航存在逆变损耗、温度、启动功率等差异，出门前拿不准带哪台。
- **AI 价值**：根据设备清单、使用时长、天气与安全余量，生成携带与补能方案。
- **商业价值**：辅助选型与配件搭配，降低错配与退货。
- **差异化**：结合用户真实设备、电池健康与历史放电效率，而非仅按理论容量估算。

### 场景 3：应急备电响应（低频高价值安全场景）

- **用户痛点**：停电时信息不透明，难以确定关键负载优先级与续航时长。
- **AI 价值**：根据当前 SOC 与实时负载预测续航，比较不同负载方案。
- **商业价值**：提升安全感、品牌信任与备电购买理由。
- **差异化**：把储能状态与安防等关键设备放进同一应急视图。
- **安全边界**：物理切换必须由认证硬件与固件完成，AI 不承担电气安全控制。

### 场景 4：语音能源管家（可选交互入口）

- **用户痛点**：双手被占用时不方便操作手机。
- **AI 价值**：用自然语言查询能源状态、解释建议、形成候选计划。
- **商业价值**：提升交互便利性与跨设备体验。
- **定位修正**：语音是**可选入口而非护城河**，首期优先 App 内按键语音；耳机深度唤醒后置。

## 四、App 功能结构（P0 / P1 / P2）

### P0 核心闭环（没有就失去竞争力）

- 能源数据接入与数据质量状态
- 地区费率、光伏、负载与 SOC 展示
- 未来 24 小时预测
- AI 优化建议及影响说明
- 用户确认、执行状态、撤销与失败反馈
- 省钱反事实基线、已验证净节省与方法说明
- 家庭、账号、设备权限与隐私管理
- 停电状态、当前续航与关键负载建议

### P1 增强体验

- 异常耗电识别、账单预算与月末预测
- 关键设备状态联动
- App 内按键语音
- 个人目标、成就与周 / 月报告

### P2 验证后扩展

- 耳机深度语音入口
- 跨品类复杂自动化
- 标准化同类家庭排行
- 积分、优惠券与碳减排展示

> 关键判断：**设备控制不是首页主价值**；首页优先展示可执行机会与已验证结果。

## 五、核心用户流程

### 流程 1：首次使用设定

选择核心目标 → 选择数据来源（储能 / 电表 / 插座 / 账单）→ 授权读取 → 检查数据完整度 → AI 建立初始基线 → 展示预计节省区间与置信度 → 给出第一条行动建议。

> 无储能设备的用户不被拦截，进入账单分析或智能电表模式。

### 流程 2：日常用电优化

检测显著机会 → 推送金额、原因与影响 → 查看「原计划 vs AI 计划」对比 → 调整或确认 → 创建定时任务 → 设备返回执行回执 → 任务完成后核算实际净节省 → 写入省钱报告。

### 流程 3：停电应急

认证硬件检测断电并完成安全切换 → App 收到状态事件 → 推送当前 SOC 与续航 → 进入应急页 → 关闭非必要负载（手机端确认）→ 硬件执行 → 实时更新负载与剩余时间 → 电网恢复后生成事件报告。

## 六、省钱量化模型

### 6.1 统一公式

```
已验证净节省 = 反事实基线成本 − 实际优化成本 − 电池循环损耗 − AI 调度额外成本
```

- 基线必须是「同样硬件、没有本次 AI 干预」的反事实成本，不能把硬件本身收益归给 AI。
- 节省**可以为负数**，不能为了展示效果强制截断为零。
- 光伏自用、储能套利、峰谷移时必须**去重**，同一度电不可重复计账。

### 6.2 三种口径

| 口径 | 含义 | 用途 |
|---|---|---|
| **保守 P20** | 只算已执行且数据完整的事件，扣除全部可识别成本 | 「已验证节省」 |
| **中等 P50** | 个性化负载、天气、费率与设备状态预测 | 今日计划与月度预测 |
| **乐观 P80** | 假设充分采纳可行建议，仍遵守安全与舒适约束 | 「可实现潜力」 |

### 6.3 收益来源

峰谷移时 · 光伏自用机会成本 · 储能套利（扣除损耗）· 减少异常耗电 · 适用的需量费用优化。

## 七、商业化方案

### 7.1 商业模式判断

「免费 App 带动硬件销售」不能直接成立，必须用**因果增量**而非相关性证明价值：

```
ROI =（增量贡献毛利 − 完整年度 TCO）÷ 完整年度 TCO
```

- 首期**不开发独立 App**，在现有能源 App 内嵌「AI 能源管家 Beta」。
- 核心研发归入储能产品能力，广告投放才是营销费用。
- 用实验组 / 对照组验证硬件转化、增购、留存与成本变化。
- 18–24 个月内没有覆盖完整 TCO 的路径，则停止扩大投入。

### 7.2 商业化验证路径

先用真实数据原型证伪需求，再投入：

```
可交互原型 + 脱敏真实数据 + 人工陪跑
→ 验证授权、信任、执行与 7 日主动复访
→ 现有 App 内小范围 MVP
→ 实验组 / 对照组验证实际节省与增量贡献毛利
→ 满足门槛后再决定独立 App 与跨品类扩张
```

> Landing Page 只能验证文案与渠道，不能证明用户会授权数据、执行建议或付费。

## 八、技术可行性

| 模块 | 可行性 | 受限 MVP 周期 | 主要风险 |
|---|---|---:|---|
| 能源数据采集 | 单一新款储能系统组合中高 | 6–8 周 | 未证实全系列统一公共 API，字段 / 粒度 / 地区碎片化 |
| AI 预测 | 复用现有智能模式中高 | 6–10 周（重建 12–16 周） | 冷启动、天气误差、预测服务能否复用 |
| App 内语音 | 中 | 4–8 周 | ASR、意图、权限、隐私、延迟 |
| 耳机深度语音 | 中低 | 12–20 周+ | 未证实可复用的语音 SDK、固件与跨团队依赖 |
| 跨品类联动 | 中 | 基础 8–12 周 | 固件、账号、离线、安全认证、幂等与回滚 |

**技术分层原则：**

1. 时间序列模型预测光伏、负载与置信区间。
2. 确定性约束优化器综合 SOC、费率、效率、损耗与安全储备。
3. **LLM 只负责解释与对话，不直接决定电力切换。**
4. 认证硬件与固件负责停电检测、安全切换与本地保护。

## 九、质疑与关键修正

方案经历过 20+ 轮红队质疑，核心修正如下：

| 原假设 | 为什么不成立 | 修正决策 |
|---|---|---|
| 只有储能用户才是有效用户 | 目标过窄，无储能用户会流失 | 改为 L1/L2/L3 分层能力 |
| 语音是核心差异化 | 能源查询低频，用户不常戴耳机 | 语音降为可选入口，推送 + 一键执行升 P0 |
| 排行与积分能提升留存 | 冷启动无样本，积分稀释真实省钱价值 | 删除公开排行与线性积分，改个人目标与里程碑 |
| 免费 App 自然促进硬件销售 | 相关性 ≠ 因果增量，TCO 可能更高 | 先内嵌 MVP 与对照实验，只算增量贡献毛利 |
| 竞品没有能源或联动能力 | 竞品已有不同程度相关能力 | 差异化改为第一方闭环与结果验证深度 |
| 首页看数据就够 | 用户不只为看数据打开 App | 首页改为「今日能源行动中心」 |

**首页钩子（修正后）**：AI 今天发现了什么、准备替我做什么、能带来多少确定收益；无事发生时保持安静，不以无意义通知制造日活。

**北极星指标**：单个接入家庭每月**经验证的净节省金额**，而非 DAU。
