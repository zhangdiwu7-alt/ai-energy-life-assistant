00Executive Summary

执行摘要与证据口径

先判断“已有能力是什么”，再决定“新系统需要建设什么”；产品页面能力不等于统一开放接口，AI 能预测也不等于可以接管电气安全。

✓
当前建议：有条件 Go，但只建设嵌入现有 能源 App 的小范围 MVP。

先服务“新款 储能系统 ＋兼容智能电表＋有峰谷/动态电价”的真实家庭，完成数据—预测—建议—确认—执行—节省验证闭环；暂不建设独立全量 App，不做 无线耳机 专属唤醒和深度固件，不承诺跨全系列设备自动联动。

中高单一新款 储能系统 的数据接入可行性
中高复用 智能模式 预测能力的可行性
中跨产品线联动的规模化可行性

证据标签

官方公开能力 方案假设 内部待确认 设计决策
口径本报告如何使用不能被误写成什么
官方公开能力储能系统智能模式 已公开具备未来发电、负载、电价预测与充放电调度；部分新设备支持本地 Modbus / Home Assistant。不等于所有 储能系统 设备具备同样能力，也不等于已有全系列统一公共 API。
内部待确认消费端内部 API、历史粒度、保留期、事件总线、跨产品账号映射、控制指令 SLA。在接口审计完成前，不作为排期和商业承诺的既定事实。
方案假设由内部设备平台提供受控读接口和低风险写接口；MVP 可使用同一 用户账号体系。不是当前对外承诺，需在 Gate 0 验证。
设计决策LLM 只解释和编排工具；电气切换、BMS 保护、逆变器并离网控制始终由认证固件和安全控制器负责。绝不描述为“AI 检测停电并直接切换供电”。
最关键的技术不确定性

不是“能否做出一个预测模型”，而是现有 储能系统 能源数据和 智能模式 输出能否通过稳定、合规、可观测的内部接口被新体验复用，并在不同代际、地区和固件上保持一致语义。

01Problem & Definition

问题分析与产品定义

用户需要的不是更多曲线，而是知道“下一步做什么、能省多少钱、执行后是否真的省到”。

信息割裂

光伏、储能、家庭负载、天气、电价与设备状态分散，用户难以形成可行动结论。

反馈滞后

电费通常到月底才被看见，用户无法在高价时段到来前干预。

价值不可信

若没有反事实基线和执行证据，“AI 帮你省钱”会退化成不可核验的营销话术。

产品定义

AI Energy Life Assistant 是“家庭能源运营助手”，不是新的设备遥控器。

系统基于用户授权的数据预测能源机会，在安全和舒适约束内生成可执行方案，经用户确认或既定授权后由设备平台执行，并以“预计节省 / 已验证节省 / 可信度”持续反馈。

净节省与解释

目标用户分层

层级可用数据可交付价值技术边界
L1 能源评估账单、地区费率、家庭问卷发现节省潜力、给出区间估算不能宣称实时监测或“已验证节省”

02Scope & Non-goals

MVP 范围与非目标

范围收缩是可行性的前提：先证明能源闭环，不为“整合三条产品线”强行制造低频功能。

优先级与交付边界

优先级能力范围说明
P0能源数据接入与质量标记一个目标市场、一组新款 储能系统＋兼容智能电表；统一 15 分钟分析粒度，实时展示单独处理。
P024 小时 PV / 负载 / 电价预测优先复用现有 智能模式；输出预测区间与更新时间，不展示虚假精确度。
P0约束优化与一键确认只生成设备能力范围内的充放电或定时计划；默认“执行前确认”。
P0节省金额账本区分预计、已执行、已验证；扣除购售电机会成本、效率损耗和电池损耗估值。
P0停电状态与续航建议读取已确认的设备状态；AI 只解释和建议，物理切换由设备固件完成。
P1App 内语音与系统快捷指令仅查询、接受建议、取消任务和应急状态；高风险操作转手机可视确认。
P1兼容智能插座自动调度能力注册、用户授权、幂等命令、执行回执均满足后灰度开放。
P2智能家居设备 / 无线耳机 深度联动以真实频率与跨团队成本验证为前置条件。

MVP 明确包含

  • 现有 能源 App 内嵌能源中心，而非新建独立 App。
  • 首页能源流、今日成本和一条高价值建议。
  • 预测、计划比较、用户确认、设备回执、结果核算。
  • 停电事件状态卡、关键负载清单和续航方案。
  • 内部审计日志、数据质量与模型监控。

MVP 明确不做

  • 无线耳机 专属唤醒词、耳机固件深度接入。
  • 全系列 储能系统、所有国家电价和任意第三方家电。
  • 公开排行榜、固定比例积分和高补贴运营。
  • 由 LLM 直接生成或发送电气安全控制指令。
  • 宣称 智能家居设备 摄像头“自动切换备用电源”；是否有电取决于物理供电回路。
  • 把 24 小时初次学习包装成稳定预测准确率。

不可跨越的安全边界

停电检测、并离网切换、逆变器保护、SOC 硬限制、过流/过温保护必须在认证设备及其固件控制回路内完成。云端 AI 可以读取结果、预测续航、提出负载方案，但不能替代保护逻辑，也不能在设备未回执时声称“已接管供电”。

关键架构原则

能力驱动

每台设备注册可读指标、可写命令、功率范围、固件门槛和风险等级；界面不展示设备实际不支持的操作。

事件驱动

状态变化通过事件总线传播，命令以异步回执闭环；不依赖 App 前台持续轮询完成关键流程。

可降级

预测不可用时回退到既有 Self-Consumption / TOU 规则；云端不可用不影响设备本地安全保护。

04Core Data Model

核心数据模型

统一模型先解决“谁、哪一户、哪台设备、什么时间、哪种能源方向、数据是否可信”，再讨论 AI。

实体核心字段关键约束 / 用途
User / Householduser_id, site_id, region, timezone, occupancy_profile一户可多用户；家庭权限分 Owner / Admin / Member / Guest。
Device / Capabilitydevice_id, model, firmware, capabilities, risk_level, online_state所有读写都以能力注册表为准；型号和固件共同决定能力。
TelemetryPointsite_id, device_id, metric, value, unit, event_time, ingest_time, quality事件时间与入库时间分离；支持迟到、去重、补数和质量标记。
TariffIntervalplan_id, start_at, end_at, import_price, export_price, currency, source购电、售电、税费分开；必须保留费率版本以便追溯。
WeatherForecastgeo_cell, valid_at, irradiance, cloud, temp, issued_at保留“发布时间”，避免用事后天气反算并美化历史预测。
Predictionmodel_version, horizon, p10, p50, p90, feature_snapshot预测值必须绑定模型版本、特征快照及置信区间。

统一口径与不变量

  • 功率与电量分离：W / kW 表示时点功率，Wh / kWh 表示区间积分，不允许互相替代。
  • 方向统一：grid.import 为正购电、grid.export 为正售电；转换在适配层完成，核心层不接收型号私有正负号。
  • 时间统一：底层存 UTC，展示按家庭时区；费率计算显式处理夏令时重复或缺失时段。
  • 质量显式：MEASURED、ESTIMATED、IMPUTED、STALE、INVALID 五档；估算数据不可冒充实测。
  • 分析粒度：MVP 以 15 分钟区间做预测、成本和基线核算；秒级/数秒级数据仅用于实时态与设备控制。

省钱账本

AI 净节省 = 反事实基线成本 − 实际成本 − 电池循环损耗 − AI 调度额外成本

基线必须是“拥有相同硬件但没有本次 AI 干预”，不能把光伏/储能硬件本身的全部收益归因给 AI；同一度电不可同时重复计入移峰、光伏自用和储能套利。

05Four Modules

四个核心模块技术方案

周期为工程估算，不是官方承诺；假设有设备平台接口负责人、现有 App 代码可复用，且各工作流可并行。

模块 A｜能源数据采集

可行性中高（单一新款 储能系统 系统）；跨全系列与第三方设备为中
周期MVP 6–8 周；多型号、多地区规模化 4–6 个月
官方基础现有 App / 智能模式 已处理光伏、家庭负载、电池与电网数据；智能电表支持本地 Modbus TCP；专业平台可展示并下载能源统计。
内部待确认消费端内部读写接口、采样/聚合/保留期、事件推送、跨账号映射、历史补数、设备命令 SLA。

MVP 实现

  1. 选择一套型号与市场建立适配器；先接入 PV、load、grid import/export、battery charge/discharge、SOC、在线/故障状态。
  2. 通过 Schema Registry 统一单位、方向、时区和质量；采用 event_id＋sequence 去重。
  3. 实时流进入事件总线和短期时序库；15 分钟聚合进入分析仓库与 Feature Store。
  4. 数据质量服务监控新鲜度、缺失率、突变、能量守恒残差及设备时间漂移。
主要风险：产品可在 App 中显示数据，并不证明存在可复用的统一 API；旧款设备、新款本地协议、地区兼容电表及固件能力需要逐一注册，不能用一个“储能系统 API”概括。

模块 B｜AI 用电与光伏预测

可行性中高（复用 智能模式）；从原始数据重建通用跨产品模型为中
周期复用服务 6–10 周；若模型不可复用，重建首版 12–16 周；规模化 6–9 个月
官方基础智能模式 已公开使用历史发电/负载、天气和电价预测未来 24 小时并生成充放电计划。
内部待确认预测服务是否可复用、输出粒度与置信区间、训练数据授权、模型覆盖市场、真实误差与线上 SLA。

模型路径

  • PV：物理先验（容量、方向/倾角若有）＋辐照/云量＋历史校准，输出 P10/P50/P90。
  • 负载：星期/时段、气温、节假日、家庭状态和滞后负载特征；新用户先用分群全局模型。
  • 电价：固定 / TOU 读取费率表；动态电价保留发布时间与版本，不允许用事后价格替代预测。
  • 冷启动：官方“最多 24 小时完成首次学习”仅代表模式可启动；产品前 1–2 周仍标“初步预测”，稳定周期由试点验证。
主要风险：官方未公开误差指标；家庭行为突变、天气偏差、智能电表断连和长期闲置都会降低准确性。不能用一个全局“准确率 90%”概括不同对象、时段和用户分群。

模块 C｜语音交互

可行性App 内语音中；无线耳机 专属唤醒与深度固件中低，公开资料不足以证明存在可直接复用的 小能 语音 SDK
周期App 内高频意图 P1：6–8 周；无线耳机 深度能力 P2：另需 3–6 个月及固件团队确认
MVP 决策不进入 MVP 先以推送＋一键操作验证能源需求；语音不承担留存和核心差异化。

模块 D｜跨设备联动

可行性中；低风险 储能系统 内部联动高于 储能系统→智能家居设备→无线耳机 全链路
周期储能系统 内部低风险命令 8–12 周；跨产品线 4–8 个月，取决于固件、账号和团队接口
MVP 决策只做设备状态读取、事件通知与受支持的 储能系统 计划；智能家居设备/无线耳机 深度联动后置。

实现要点

  • Capability Registry 定义每台设备可读、可写、功率/时间范围、风险级别、固件要求和是否支持回滚。
  • Command Gateway 负责授权、幂等键、过期时间、签名、防重放、速率限制与异步回执。
  • 编排器只向已认证能力发命令；部分设备失败时逐项展示，不用“全部成功”掩盖失败。
  • 停电时 储能系统 固件先检测并完成受支持的本地切换，云端随后接收状态事件；AI不在物理切换关键路径中。
  • 智能家居设备 摄像头能否继续在线由它所在物理回路、网络设备和备用供电决定，不能通过软件凭空“切换备用电源”。
06AI Responsibility

AI 预测、约束优化与 LLM 的职责边界

把“会说话的模型”和“可审计的控制决策”分开，是能源场景可靠性的核心。

组件负责明确不负责输出
时间序列预测未来 PV、家庭负载、电价及不确定性不直接下设备命令，不绕过用户偏好15 分钟 P10/P50/P90 序列
反事实基线估算“没有本次 AI 干预”的成本不把硬件天然收益全部归因给 AI基线成本、可信度、证据引用
约束优化器在设备、安全、舒适与费率约束内最小化净成本不修改固件硬限制，不执行未经授权动作候选计划、收益、影响与约束
Policy Guard权限、风险级别、确认规则、禁用清单不依赖 LLM 自我约束ALLOW / CONFIRM / DENY
LLM解释、追问、结构化工具调用、对话摘要不自行计算最终账单、不直接控制逆变器/电气切换自然语言＋受控工具请求
设备固件 / EMS / BMS物理控制、并离网保护、SOC/温度/功率硬限制不接受越权云端覆盖执行回执、故障与真实状态

优化目标与约束

min Σₜ [购电ₜ × 买价ₜ − 售电ₜ × 卖价ₜ] + 电池损耗成本 + 违约惩罚

硬约束

  • SOC 上下限、充放电功率、逆变器能力。
  • 同一时段不可非法同时充放电。
  • 设备能力、固件禁令、并网规则。
  • 关键负载和医疗设备永不由 AI 自动关闭。

用户约束

  • 备电最低比例、任务完成时间。
  • 可延迟设备清单与免打扰时段。
  • 舒适度偏好、自动化等级。
  • 本次可接受费用或风险上限。
执行铁律：LLM 输出永远不能直接映射成设备协议报文。它只能调用受类型约束的业务工具；工具服务重新校验权限、参数、计划有效期和设备能力后，才允许进入 Command Gateway。

08Key Sequences

三个关键时序

每个流程都必须到达“可核验结果”；应急流程先由设备保证安全，再由云端提供解释与优化。

时序一｜首次接入与个人报告

用户 → App登录并选择家庭；授权读取能源、费率与位置/天气用途。非必要权限可跳过；用途和保留期逐项说明。
App → Identity校验家庭角色与设备归属，签发最小权限 token。
BFF → Device Platform读取兼容设备、能力、固件和历史可用范围；不假定全系列统一 API。
Data Quality统一单位/时区，评估完整度、新鲜度和异常；生成 Data Readiness。
Forecast / Baseline有足够数据则运行预测；不足时使用分群先验并标“初步估算”。
App → 用户展示年度节省区间、前三项机会、计算依据与可信度；邀请开启第一条“执行前确认”规则。

时序二｜日常用电优化

数据 / 预测服务在滚动窗口更新 PV、负载与电价预测；数据过旧则停止生成自动建议。
约束优化器生成“原计划 vs 新计划”，计算预计净节省、完成时间和约束影响。
Policy Guard校验设备能力、用户权限、风险等级、建议阈值和免打扰策略。
通知 → 用户推送“推迟洗碗机预计省 $0.35”；用户查看依据后确认或修改。
Command Gateway重验计划未过期、设备在线与参数安全，带幂等键下发定时。
设备平台 → App返回逐设备回执；失败或未知明确展示，并提供取消/重试。
Savings Engine任务完成后对账实际电量和费率，写入已验证净节省；预测与实际分开显示。

时序三｜停电应急

设备固件本地检测电网异常并按认证逻辑完成受支持的切换与保护。AI 和云端不在物理安全关键路径。
设备平台上报 outage detected；只有收到 backup supply confirmed 后，App 才写“储能设备 已接管”。
应急服务基于 SOC、实时负载、设备状态和数据新鲜度计算续航区间。
推送 → 用户优先告知市电状态、是否确认备电、当前关键负载与预计续航。
优化器给出安全优先 / 均衡 / 最长续航方案；医疗与关键设备保留。
用户确认批量关闭属于高影响操作，需手机可视确认；只控制明确支持且物理在可控回路内的设备。
设备回执 / App逐项反馈执行结果并重新计算续航；断网时展示本地可得状态和最后云端更新时间。
09Security & Privacy

权限、安全与隐私

能源曲线可推断作息和是否在家，控制权限又可能影响真实设备，因此按高敏感家庭数据设计。

权限模型

角色读取控制授权管理
Owner家庭全部授权数据可确认支持的 L1/L2 操作可授予、撤销、导出与删除
Admin按 Owner 授权可确认非安全类操作不可删除 Owner 或扩大自身 scope
Member摘要与设备状态仅低风险、可逆操作不可新增第三方数据连接
Guest受限状态无远程控制无
Support用户主动授权的脱敏诊断默认无控制短时、可撤销、全审计

控制分级

L0 查询

用电、发电、费率；直接返回，但需显示数据时间。

L1 可逆

普通定时、暂停建议；复述后一次确认。

L2 高影响

储能底线、批量关闭、EV充电；手机可视确认。

L3 安全

并离网、保护阈值、医疗负载；云端 AI 禁止直接执行。

安全与隐私控制

  • 传输与存储：TLS 1.2+；敏感数据和 token 加密存储；密钥由 KMS 管理并定期轮换。
  • 认证授权：短期访问 token、设备绑定、细粒度 scope；高风险操作重认证与防重放。
  • 目的限定：“提供能源建议”与“训练通用模型”分开授权；默认不把家庭数据用于无关营销。
  • 最小化：LLM 上下文仅发送完成当前任务所需的聚合数据；设备序列号、精确地址和原始能源曲线脱敏或不发送。
  • 生命周期：定义原始遥测、聚合、语音文本、审计日志各自保留期；支持导出、撤回和删除。
  • 审计：记录谁在何时基于何种授权查看数据、确认计划、下发命令和修改自动化等级。
  • 合规：按上线地区完成 GDPR / UK GDPR / CCPA 等评审、数据驻留和跨境传输评估。
威胁重点：账号接管、家庭成员越权、命令重放、伪造设备回执、恶意提示注入、第三方天气/电价污染、模型输出诱导高风险操作。安全测试需覆盖 API、移动端、设备云、事件总线与 LLM 工具调用全链路。
10Reliability & Degradation

可靠性、离线与降级策略

“关键时刻可靠”不是让所有能力离线运行，而是明确哪些必须本地完成、哪些可以安全停止。

故障系统行为用户表达禁止行为
智能电表断连停止自动优化；回退既有安全模式；最后数据标 STALE“电表数据更新于 18 分钟前，自动优化已暂停”继续累计“已验证节省”
天气服务不可用使用最近预报＋历史基线，扩大区间；低置信建议不推送“天气数据不足，预测区间已扩大”展示单点精确发电量
动态电价不可用使用已发布费率或停止价格套利“暂按最近有效费率估算”基于过期价格自动充放电
预测 / 优化服务不可用回退 Self-Consumption / TOU 规则“智能建议暂不可用，设备继续按原计划运行”影响 BMS / EMS 本地保护
云端或家庭互联网中断设备固件维持保护与既有计划；本地能力按支持型号运行App 显示最后同步时间声称远程命令已成功
命令超时标 UNKNOWN，读取真实状态对账；不盲目重发非幂等命令“尚未确认执行，请检查设备状态”把超时当成功
智能家居设备 / 无线耳机 不可用能源核心闭环继续；隐藏相关增强入口“该入口暂不可用，可在 App 中继续”阻塞 储能系统 计划
LLM 不可用使用模板解释结构化结果仍可查看数据、确认或取消计划让能源决策依赖对话服务在线

建议 SLO（MVP 目标）

  • 能源读取 API 月可用性 ≥ 99.5%；建议和报告可低于设备保护链路，二者不得共用单点。
  • 云端收到设备事件后，应急状态推送 p95 ≤ 30 秒；该指标不包含本地物理检测和切换时间。
  • 普通命令确认链路 p95 ≤ 5 秒；超时进入 UNKNOWN 并对账。
  • 15 分钟数据桶完整率 ≥ 98%；质量不足时自动禁用节省验证与自动优化。
  • RPO：配置与账本 ≤ 5 分钟；RTO：核心读取 ≤ 60 分钟。最终值由平台等级和成本评审确定。
11Verification

测试策略与验收指标

“模型好像准确”和“页面能点通”都不构成上线证据；必须同时验证数据、经济性、安全、可靠性和真实用户行为。

层级测试内容建议验收门槛
数据契约单位、正负号、时区、乱序、迟到、重复、设备升级兼容标准样例 100% 通过；关键指标错向/错单位为 0
数据质量15 分钟桶完整度、延迟、守恒残差、异常值试点户完整率 ≥98%；异常会被标记且不会进入已验证账本
预测按型号、地区、季节、新老用户评估负载 WAPE 与 PV nMAE相对季节性朴素基线误差至少下降 15%；P10–P90 覆盖率接近目标区间
优化与规则基线、事后最优对比；检查成本、舒适和设备约束线上平均净成本不劣于原策略；硬约束违规为 0
节省核算购售电、效率、电池损耗、重复归因、费率变更与独立账单计算偏差 ≤1%；重复计账为 0
命令幂等、超时、部分失败、撤销、过期计划、权限变化重复物理执行为 0；所有失败可定位并呈现
安全越权、重放、token 泄漏、事件伪造、提示注入、工具越界高危漏洞为 0；L3 操作被云端/语音直接执行为 0
应急断网、断云、停电模拟、旧数据、错误回执本地保护不受云服务影响；未确认备电时不展示成功
语音（P1）查询、接受、取消、歧义、噪声、敏感操作核心意图任务完成率 ≥90%；高风险误执行为 0
用户试点授权、建议采纳、主动复访、可信度、投诉以原型验证门槛为准；技术通过不等于商业通过

模型评估规范

  • PV 只在有效日照时段评估，夜间大量 0 不得稀释误差。
  • 禁止随机打散时间序列；使用滚动时间窗回测，防止未来信息泄漏。
  • 天气预测必须使用当时可获得的 forecast vintage，而非事后实况。
  • 上线前影子运行 2–4 周，只比较建议与既有模式，不下发自动命令。
  • 除平均指标外报告 P90 误差、最差地区/型号、冷启动与断连人群。

13Plan & Dependencies

开发排期、人员与关键依赖

总周期取决于 Gate 0：若内部接口不可复用或预测服务封闭，排期应重估，而不是用加班掩盖架构前提失效。

建议 14–16 周受控生产 MVP

口径说明：产品验证可先用 8–12 周的只读数据、建议、人工确认和有限执行 Beta；以下 14–16 周排期进一步包含受支持低风险命令、质量监控、硬件在环、安全审计和 50–100 户受控发布，两者不是同一交付成熟度。
第 0–2 周｜技术尽调与范围冻结
盘点接口、事件、数据保留、设备/固件矩阵、智能模式 复用方式、目标市场电价；完成隐私与安全威胁建模。
Gate 0 若核心数据无受支持接口，暂停开发。
第 2–6 周｜数据底座与体验骨架
统一 Schema、单型号适配、时序入库、质量监控、账号授权、首页实时能源流和历史曲线。
第 4–10 周｜预测、基线与节省账本
复用或建立 24 小时预测服务；完成费率、天气、反事实基线、置信区间和账本；进入影子运行。
第 7–12 周｜约束优化与低风险命令
候选计划、Policy Guard、用户确认、Command Gateway、幂等回执、取消和回退。
第 10–14 周｜应急状态与端到端加固
设备状态事件、续航区间、故障/离线降级、隐私安全测试、硬件在环和客服预案。
第 14–16 周｜50–100 户受控 Beta
分群测量数据质量、预测增益、建议采纳、真实净节省、投诉和命令稳定性；召开 Gate 2。

排期加法：若没有可复用预测服务，增加约 6–10 周；若必须新建独立 App 和账号迁移，增加约 8–12 周；若 MVP 同时加入 智能家居设备 / 无线耳机 固件联动，风险不可简单线性估算，应另立项目。

15Decision Gates

Go / No-Go 决策门槛

每一道门都可以停止项目；“已投入成本”不能成为继续扩大投入的理由。

GateGo 条件No-Go / 收缩条件
Gate 0｜接口可行
第2周		目标组合有受支持读接口；字段、历史和授权明确；至少有一个安全的低风险命令路径。只能逆向 App 私有接口；数据语义不可追溯；设备团队不承诺接口维护。
Gate 1｜技术 Alpha
第10–12周		数据完整率达标；预测优于朴素基线；硬约束违规为0；账本可对账；命令幂等。预测无增益、净节省为负、设备回执不可靠或存在安全越界。
Gate 2｜用户 Beta
第16周		用户愿意授权；建议被真实执行；看到结果后主动复访；投诉和打扰可控。用户只看报告不行动、拒绝数据授权、节省不足以形成价值或信任崩溃。
Gate 3｜商业扩张实验组相对对照组的增量贡献毛利、服务收入或成本下降可覆盖完整 TCO，回收期符合公司标准。只有相关性没有因果增量；完整成本高于可验证收益；目标市场规模不足。
→
本报告最终判断

有条件 Go 在 Gate 0 通过后，先完成 8–12 周验证 Beta；证据通过后再加固为 14–16 周成熟度的单市场、单设备组合、现有 App 内嵌 储能系统 能源 MVP。No-Go 直接投入完整独立 App、全产品线统一控制、无线耳机 深度语音或由 AI 承担电气安全切换。

内部必须确认的 12 项
  1. 消费端能源数据读接口的正式 owner、文档、鉴权、限流和版本策略。
  2. 控制接口的命令语义、风险级别、幂等、回执、超时和 SLA。
  3. 原始/聚合数据的采样、保留、补数、导出和删除能力。
  4. 家庭、站点、用户和设备 ID 在 储能系统、智能家居设备、无线耳机 间的映射。
  5. 智能模式 模型服务是否可跨 App 复用，还是绑定设备端固件。
  6. 预测输出的粒度、置信区间、版本、训练授权和真实分群误差。
  7. 各型号/固件的能力注册、OTA 向后兼容和停止支持策略。
  8. 停电、备电确认、故障和恢复事件的来源、顺序与可靠性。
  9. 旗舰储能系统 Open API / Modbus 的正式开发文档、地区、读写范围和安全模型。
  10. 电价与天气供应商许可是否允许模型训练、账单计算和用户展示。
  11. 数据驻留、跨境、模型训练、语音文本与审计日志保留政策。
  12. 完整 TCO：研发、云/AI、数据、固件、合规、客服与长期维护。
